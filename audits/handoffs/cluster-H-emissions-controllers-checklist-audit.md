## Scope

Two Intuition-chain emissions contracts:

- **`CoreEmissionsController`** — a stateless-after-init emissions *schedule oracle*. Holds the schedule params (`_START_TIMESTAMP`, `_EPOCH_LENGTH`, `_EMISSIONS_PER_EPOCH`, `_EMISSIONS_REDUCTION_CLIFF`, `_EMISSIONS_RETENTION_FACTOR`) set once in `__CoreEmissionsController_init`, and exposes pure/view epoch math: epoch-at-timestamp, epoch start/end (closed intervals), per-epoch emissions with compound cliff reductions (`rpow`/`mulWad` at `1e18` scale). No mint, no token custody, no admin setters — it is the arithmetic backbone that `TrustBonding` routes **all** reward-epoch math through (`getEpochLength`, `getEpochAtTimestamp`, `getEpochTimestampEnd`, `getEmissionsAtEpoch`).
- **`SatelliteEmissionsController`** — the Intuition-chain custodian of native TRUST. Inherits `CoreEmissionsController` (schedule) + `MetaERC20Dispatcher` (bridge transport) + `AccessControlUpgradeable` + `ReentrancyGuardUpgradeable`. It (a) pays user rewards on behalf of `TrustBonding` via `transfer` (`CONTROLLER_ROLE`), and (b) reclaims each epoch's *unclaimed* emissions once that epoch is no longer claimable, either by admin `withdrawUnclaimedEmissions` (`DEFAULT_ADMIN_ROLE`) or by `bridgeUnclaimedEmissions` (`OPERATOR_ROLE`) back to `BASE_EMISSIONS_CONTROLLER`. A per-epoch `_reclaimedEmissions` flag is the double-spend guard shared by both reclaim paths.

**In scope (§6.H):** the CoreEmissionsController schedule arithmetic (epoch length, per-epoch amount, cliff/retention, epoch boundaries, epoch 0), and the SatelliteEmissionsController TRUST-transfer/reclaim accounting *out of* TrustBonding (reclaim/replay, double-transfer), plus access control on the controller/operator roles and initializers.

**Explicitly out of scope (§3), boundary noted and not filed:** the cross-chain **dispatch/transport leg** — `MetaERC20Dispatcher._bridgeTokensViaNativeToken` / `_quoteGasPayment`, the MetaLayer router / `IMetaERC20HubOrSpoke` / IGP, and finality/gas-limit semantics. **`BaseEmissionsController`** and all Base-chain mint/funding is out of scope; where the reclaim math's solvency depends on how much native TRUST Base bridges in, that is recorded as an **Open Question / cross-boundary assumption**, not a finding on the in-scope code (which is internally consistent). No ERC20/4626, oracle, AMM, merkle, signature, or inline-assembly surface exists in either contract.

**Headline result:** no Critical, High, or Medium issue confirmed on this surface. The schedule arithmetic is boundary-correct (closed intervals, no off-by-one, division-by-zero only from the one unvalidated param below); the reclaim path is replay-safe (CEI + per-epoch flag, mutually exclusive with the claim window by construction); and role/initializer gating is sound (atomic proxy init, `_disableInitializers`, role-gated mutators). Findings: **1 Low (confirmed duplicate of Fable-H-01)**, plus 1 configuration risk, 4 Informational, and 3 Open Questions. **Cluster verdict: PASS.**

## Findings

### [Low] `emissionsLength` (`_EPOCH_LENGTH`) accepted without a non-zero validator → division-by-zero → protocol-wide DoS on misconfig (ref: SOL-Basics-Math-6, SOL-Basics-Function-1, SOL-Basics-Function-5, SOL-Basics-Initialization-1)

- **Status:** **Confirmed (dup Fable-H-01)** — independently reproduced by this round's reasoning.
- **Location:** `CoreEmissionsController.sol:61` (`_EPOCH_LENGTH = emissionsLength`, assigned with **no validator**), contrasted with the four sibling params each validated at `CoreEmissionsController.sol:55-58` → `130-152`. The div-by-zero sites are `_calculateTotalEpochsToTimestamp` (`:217`, `(timestamp - _START_TIMESTAMP) / _EPOCH_LENGTH`) and `_epochsPerYear` on the consumer side (`TrustBonding.sol:544`). Only reachable via `SatelliteEmissionsController.initialize` (`:77-83`).
- **Impact:** If `emissionsLength == 0` is passed at init, the contract deploys and initializes cleanly, then **every** epoch query reverts on the first division: `getCurrentEpoch`, `getEpochAtTimestamp`, `getEpochTimestampEnd`, `getEmissionsAtTimestamp`. Because `TrustBonding` funnels all epoch math through the satellite (`TrustBonding.sol:154,548,552,560`), the entire bonding/claim/utilization system is bricked with **no non-upgrade recovery** — there is no post-deploy schedule setter anywhere in `CoreEmissionsController` (the params are write-once).
- **Exploit path:** Not attacker-reachable. `initialize` is `initializer`-gated and, in the deploy path, atomically driven by the deployer / 4-of-8 Safe (see Config note). This is a **trusted-admin fat-finger footgun**, filed per the handoff mandate to "note trusted-admin actions separately," and because it is a silent, unrecoverable-without-upgrade break of a load-bearing invariant.
- **Proof of concept (numbered):**
  1. Deploy `SatelliteEmissionsController` proxy with `CoreEmissionsControllerInit.emissionsLength = 0` (all other params valid). `initialize` succeeds — `_validateTimestampStart/_validateEmissionsPerEpoch/_validateCliff/_validateReductionBasisPoints` all pass; nothing checks `emissionsLength`.
  2. `vm.warp(start + 1)`; call `satellite.getCurrentEpoch()` → `_calculateTotalEpochsToTimestamp` computes `1 / 0` → revert (panic 0x12).
  3. Every `TrustBonding` entry that reads `currentEpoch()` / `epochTimestampEnd()` / `emissionsForEpoch()` reverts → `claimRewards`, `_userEligibleRewardsForEpoch`, and the reclaim views are all DoS'd.
- **Recommendation:** Add a validator alongside the existing four:
  ```solidity
  function _validateEpochLength(uint256 emissionsLength) internal pure {
      if (emissionsLength == 0) revert CoreEmissionsController_InvalidEmissionsLength();
      // optional upper bound to prevent an absurd length that freezes epoch 0 forever
  }
  ```
  and call it in `__CoreEmissionsController_init` before `_EPOCH_LENGTH = emissionsLength`.
- **Regression test:** `test_init_revertsWhenEpochLengthZero` (mutation-check: passes only with the validator present).
- **Variant sweep:** only `emissionsLength` lacks a validator; `emissionsPerEpoch`/`startTimestamp`/`cliff`/`reductionBasisPoints` are each covered (`:130-152`). No other zero-divisor: `_EMISSIONS_REDUCTION_CLIFF` is guarded `!= 0` at `:149`, and `BASIS_POINTS_DIVISOR`/`1e18` are constants.

## Configuration risk (go-live decision)

### [Low, config-contingent] Dual, independently-set epoch length: satellite `_EPOCH_LENGTH` vs TrustBonding/VotingEscrow `BONDING_EPOCH_LENGTH` (ref: SOL-CR-7, SOL-Heuristics-1, SOL-Basics-Function-4)

- **Location:** `SatelliteEmissionsController.initialize` sets `_EPOCH_LENGTH = checkpointInit.emissionsLength` (`CoreEmissionsController.sol:61`), which `TrustBonding` uses for **all reward-epoch math** via `getEpochLength()` (`TrustBonding.sol:154,544,548,552`). Separately, `TrustBonding.initialize` passes a distinct `_epochLength` (`BONDING_EPOCH_LENGTH`) into `__VotingEscrow_init` (deploy: `script/intuition/IntuitionDeployAndSetup.s.sol:283`), which governs lock mechanics (`MINTIME`, decay). These are **two separate constants** with no on-chain equality check.
- **Impact:** The `totalBondedBalanceAtEpochEnd` / `userBondedBalanceAtEpochEnd` snapshot-at-epoch-end safety argument in `TrustBonding.sol:201-235` explicitly rests on `MINTIME >= EPOCH_LENGTH` ("production: both `= 2 weeks`"). If the satellite's emissions epoch is **shorter** than the VotingEscrow epoch, a lock could be created/extended and exit within a single reward epoch, weakening the "forced to remain a real participant" guarantee and desyncing reward epochs from lock decay. The mainnet/testnet setup blocks keep them equal (`EMISSIONS_LENGTH = TWO_WEEKS = BONDING_EPOCH_LENGTH`, `script/SetupScript.s.sol:200/230`, `:236/283`, `:254/283`, `:289/318`), **but one local/dev block diverges** (`EMISSIONS_LENGTH = ONE_DAY` while `BONDING_EPOCH_LENGTH = TWO_WEEKS`, `script/SetupScript.s.sol:318/324`), proving the two are hand-kept in sync rather than structurally coupled.
- **Recommendation:** Make equality an explicit go-live assertion in the deploy/verification script (`require(EMISSIONS_LENGTH == BONDING_EPOCH_LENGTH)` for any non-dev chain), or derive TrustBonding's VotingEscrow epoch from `satellite.getEpochLength()` at init so a single source of truth governs both. No in-scope source change strictly required; this is a parameterization/consistency gate. Note this is a cross-contract concern that also touches cluster F.
- **Status:** Open — config gate for mainnet (mainnet configs currently consistent).

## Open questions for the developer

- **OQ-1 — Reclaim solvency depends on Base funding == `maxEmissions` per epoch (cross-boundary).** `getUnclaimedRewardsForEpoch` reclaims `getEmissionsAtEpoch(epoch) − totalClaimedRewardsForEpoch[epoch]` = **max** (schedule) emissions minus claimed, *not* the utilization-adjusted amount (`TrustBonding.sol:372-375`, and the explicit comment there). For the satellite to hold enough native TRUST to satisfy both user `transfer`s and the reclaim, `BASE_EMISSIONS_CONTROLLER` must bridge **exactly `maxEmissions` per epoch**. If Base ever funds only the utilization-adjusted amount, `withdraw`/`bridge` would draw against other epochs' balances or revert on `Address.sendValue` insufficiency. Base is out of scope (§3); confirm the Base mint/bridge schedule funds `getEmissionsAtEpoch(epoch)` per epoch so the in-scope reclaim math is solvent (**SOL-CR-1, SOL-AM-DOSA-6**).
- **OQ-2 — Reclaim window vs claim window separation is by construction; confirm the "≥2 epochs old" gap is the intended forfeiture policy.** An epoch is claimable only while `currentEpoch == epoch+1` (`claimRewards` targets `currentEpoch-1`, `TrustBonding.sol:396`) and reclaimable only once `epoch <= currentEpoch-2` (`TrustBonding.sol:359-368`). The two windows are disjoint, so there is no claim/reclaim double-spend — but it also means a user who does not claim in epoch `N+1` **permanently forfeits** epoch `N`'s reward to the reclaim path (aligns with the "rewards forfeited if not claimed before the next epoch ends" NatSpec, `TrustBonding.sol:28-29`). Confirm this forfeiture-to-reclaim boundary is intended (it is the same tradeoff as Fable-F-01).
- **OQ-3 — `CONTROLLER_ROLE` / `OPERATOR_ROLE` are not granted in `initialize`.** `initialize` grants only `DEFAULT_ADMIN_ROLE` (`SatelliteEmissionsController.sol:93`); `CONTROLLER_ROLE` (needed by `TrustBonding` for `transfer` → `claimRewards`) and `OPERATOR_ROLE` (needed for `bridgeUnclaimedEmissions`) must be granted post-deploy by the admin Safe. On mainnet the deploy script defers both to the Safe (`script/intuition/IntuitionDeployAndSetup.s.sol:294-303` grants CONTROLLER_ROLE only off-mainnet; OPERATOR_ROLE is never granted in-script). Confirm the mainnet runbook grants `CONTROLLER_ROLE` to TrustBonding (else all reward claims revert) and `OPERATOR_ROLE` to the bridge operator, and that no unintended address holds either.

## Acknowledged non-issues (properties checked and cleared)

Each line is a §6.H hypothesis that was **attempted and refuted**, with the defending guard cited — the "we looked here and it held" evidence.

- **PASS — Reclaim replay / double-spend across `withdraw` and `bridge`** (SOL-AM-ReplayAttack-1, SOL-Heuristics-12, SOL-Heuristics-16). Tried reclaiming the same epoch twice, and via the *other* function. Defended: both paths check `_reclaimedEmissions[epoch] > 0` and revert `PreviouslyBridgedUnclaimedEmissions` (`:202,228`), and both set `_reclaimedEmissions[epoch] = amount` **before** any external transfer (`:207` then `:210`; `:233` then `:243`) — CEI. The two paths are mutually exclusive via the shared flag; the reclaim amount is frozen because the epoch is no longer claimable (`totalClaimedRewardsForEpoch[epoch]` can only change for `currentEpoch-1`) and `getEmissionsAtEpoch` is time-invariant.
- **PASS — Claim/reclaim window overlap** (SOL-Heuristics-3, SOL-Heuristics-16). Tried to reclaim an epoch still claimable by users (or claim one already reclaimed). Defended: claim window (`currentEpoch-1`) and reclaim window (`≤ currentEpoch-2`) are disjoint by construction (`TrustBonding.sol:359-368,396`); an epoch stops being claimable exactly one epoch before it becomes reclaimable.
- **PASS — Epoch-boundary / epoch-0 / cliff-boundary arithmetic** (SOL-Heuristics-7, SOL-Basics-Math-1, SOL-Basics-Math-10, SOL-Basics-AL-1). Verified closed-interval consistency: `getEpochAtTimestamp(getEpochTimestampStart(N)) == N` and `getEpochAtTimestamp(getEpochTimestampEnd(N)) == N` (end = `start + (N+1)*length - 1`, `:183-185`); epoch 0 = `[start, start+length-1]` with full base emission (`cliffsPassed = 0/cliff = 0`, `:160`); first reduction lands exactly at `epoch == cliff` (`cliffsPassed = 1`), i.e. start of year 2 for `cliff=26 × 2-week` — matching `EMISSIONS_PER_EPOCH = ONE_YEAR/26`. No off-by-one; `block.timestamp < start` returns 0 (`:167,193,213`).
- **PASS — Division-by-zero beyond `_EPOCH_LENGTH`** (SOL-Basics-Math-6). `_EMISSIONS_REDUCTION_CLIFF` is guarded `!= 0` (`:149`), so `epoch / _EMISSIONS_REDUCTION_CLIFF` (`:160,201`) is safe; `BASIS_POINTS_DIVISOR` and `1e18` are non-zero constants. Only `_EPOCH_LENGTH` is unvalidated (see Low finding).
- **PASS — `_applyCliffReductions` overflow / max-value** (SOL-Basics-Math-7, SOL-Basics-Math-12, SOL-Basics-Type-1). `rpow(rWad ≤ 1e18, cliffs)` ≤ `1e18` (retention ≤ 10000 ⇒ rWad ≤ 1e18, monotone non-increasing), `mulWad(base, factorWad) = base*factorWad/1e18` with `base·1e18` well within uint256. Large `epoch` inputs to `getEmissionsAtEpoch` decay `factorWad` to 0 (returns 0, no revert). No max-supply cap needed — the satellite never mints; it only custodies/forwards native TRUST already funded by Base.
- **PASS — `transfer` (CONTROLLER_ROLE) reentrancy / griefing** (SOL-AM-Reentrancy-2, SOL-EC-13, SOL-Basics-Payment-1). `transfer` is `nonReentrant` (`:134`), checks `recipient != 0`, `amount != 0`, `balance >= amount` (`:135-137`), then `Address.sendValue`. A reverting recipient reverts the whole `claimRewards` (TrustBonding state rolls back — user retries with another recipient); the recipient is user-chosen, so no cross-user griefing. No satellite state is mutated after the send.
- **PASS — Access control on mutators / initializers** (SOL-Basics-AC-2, SOL-Basics-AC-9, SOL-Basics-PU-2, SOL-Basics-PU-5, SOL-Basics-Initialization-3). Constructor calls `_disableInitializers()` (`:56-58`); `initialize` carries `initializer` and reverts on `admin == 0` (`:67,69`); every setter is `onlyRole(DEFAULT_ADMIN_ROLE)` (`:149-176`), `transfer` is `onlyRole(CONTROLLER_ROLE)`, `bridge` is `onlyRole(OPERATOR_ROLE)`. `initialize` front-running is closed by **atomic** proxy construction+init in the deploy script (`TransparentUpgradeableProxy(impl, timelock, initData)`, `IntuitionDeployAndSetup.s.sol:266-268`).
- **PASS — Admin setter events / config validation** (SOL-CR-5, SOL-CR-7). All setters emit (`TrustBondingUpdated`, `BaseEmissionsControllerUpdated`, `MessageGasCost/FinalityState/RecipientDomain/MetaERC20SpokeOrHubUpdated`); `_setTrustBonding`/`_setBaseEmissionsController`/`_setMetaERC20SpokeOrHub` reject `address(0)` (`:264,272`, `MetaERC20Dispatcher.sol:105`).
- **PASS — Storage layout / upgrade safety** (SOL-Basics-PU-9, SOL-Basics-PU-10). `forge inspect` confirms CoreEmissionsController occupies slots 0–4 + `__gap[50]` at slot 5; the satellite linearizes cleanly (OZ v5 namespaced AccessControl/ReentrancyGuard take no sequential slots; CoreEmissions 0–4, gap 5–54, MetaERC20Dispatcher 55–56, gap 57–106, satellite state `_TRUST_BONDING`/`_BASE_EMISSIONS_CONTROLLER`/`_reclaimedEmissions` 107–109, gap 110–159). No overlap; satellite is greenfield in v1.1.0 (frontier: "diff is import-only").
- **PASS — `tx.origin`, delegatecall, inline assembly, unbounded loops, cross-chain timestamp assumptions** (SOL-Basics-AC-7, SOL-EC-3/10/11, SOL-McCc-1). None used. No loops in either contract; the only external calls are `Address.sendValue` and the out-of-scope bridge dispatch. Epoch math uses the satellite's own `block.timestamp` only (no cross-chain timestamp comparison in-scope).
- **PASS — `msg.value` accounting in `bridgeUnclaimedEmissions`** (SOL-Basics-Payment-2, SOL-EC-2). Verified: operator supplies `msg.value >= gasLimit` (`:237-239`); the bridge call consumes `gasLimit + amount` (gas from `msg.value`, `amount` from held balance) and the excess `msg.value − gasLimit` is refunded to `msg.sender` (`:252-254`), so net balance falls by exactly `amount` and `msg.value` is fully accounted. (The gas-quote correctness and the `GAS_CONSTANT + _messageGasCost` vs `GAS_CONSTANT` argument split are on the out-of-scope transport leg.)
